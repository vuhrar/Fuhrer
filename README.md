# Führer — منصة العمل القانوني الموثق

تم تطوير المشروع ليكون تطبيق PWA يعمل عبر **FastAPI + HTML/CSS/JavaScript**، ويقدم أدوات قانونية عملية لمستخدم واحد. لم يعد التركيز على الحاسبات المالية؛ المسار الحالي يركز على قراءة النصوص، استخراج الالتزامات، اكتشاف مؤشرات المخاطر، تجهيز قائمة الأدلة، والبحث في مصادر رسمية قابلة للفتح والتحقق.

> **تنبيه مهني:** المخرجات مساعدة أولية وليست رأيًا قانونيًا نهائيًا. يجب على محامٍ مؤهل التحقق من الوقائع، النص النافذ، التاريخ، الاختصاص، وأي تعديل لاحق قبل اتخاذ إجراء.

## مساحة العمل القانونية

النسخة الاحترافية تضيف مساحة عمل محلية بقاعدة SQLite، وتفصل بين التحليل القانوني وبين إدارة الملف. يمكن إنشاء قضية أو علاقة تعاقدية، تسجيل العميل والطرف المقابل والاختصاص والأولوية، إضافة مهام بمواعيد، ربط المستندات المستخرجة بالملف، ومراجعة سجل التدقيق الذي يسجل إنشاء القضية والمهام والمستندات. هذا يجعل التطبيق أقرب إلى نظام تشغيل عمل قانوني منه إلى صفحة تحليل منفردة.

المسارات الأساسية لمساحة العمل هي `GET /api/dashboard`، و`GET/POST /api/matters`، و`GET/PATCH /api/matters/{matter_id}`، و`POST /api/matters/{matter_id}/tasks`، و`PATCH /api/tasks/{task_id}`. يمكن رفع المستندات وربطها بملف عبر الحقل `matter_id` في `POST /api/upload`.

| استخراج الالتزامات | تحليل لغوي حتمي | الطرف، صيغة الالتزام، النص المستخرج، وضرورة المراجعة |

| قائمة الأدلة | ربط موضوع الواقعة بالمستند المطلوب | المستندات المقترحة وأولوية الإحضار |
| البحث القانوني | فهرسة TF-IDF فعلية (char n-grams) على ~260 مادة (منسّقة + مستخرجة آليًا)، مع مسار ترقية للتضمينات الحقيقية | نتائج مرتبة بالصلة الفعلية، مع وسم مستوى الثقة وحاجة التحقق لكل نتيجة |
| حاسبة الاستحقاقات | مُعاد بناؤها بالكامل، كل رقم مُسنَد لنص مادته | مكافأة نهاية خدمة (م84)، حد أدنى تعويض فصل تعسفي (م77)، عمل إضافي (م106)، إجازة سنوية (م109)، حقوق تأخير الأجر (م90) بلا نسبة مخترعة |
| ورقة العمل الشاملة | تجمع كل الحاسبات في تقرير منهجي واحد | إجمالي موثوق + بنود صريحة "بحاجة معلومة إضافية" بدل اختلاق أرقام لها |
| محرك المواعيد والتقادم | حساب مباشر مُسنَد (م222 للتقادم، م78 للإشعار) | تاريخ تقادم دقيق، أيام متبقية، درجة استعجال |
| فحص مشروعية الإنهاء | قائمة تحقق مُسنَدة (م77/78/80/81)، بلا نسبة نجاح مُخترعة | المسار النظامي الأرجح + الأدلة المطلوبة تحديدًا لكل مسار |
| تحليل المراسلات الإلكترونية | قواعد نصية صريحة (لا AI)، اقتباس حرفي إلزامي، تفسيرات متعددة لا حكم جازم | مؤشرات لصالح المستخدم وأخرى قد تُستخدم ضده، ربط متقاطع، جدول زمني |
| صياغة طلب التسوية الودية (تراضي) | يبني من وقائع/طلبات القضية الفعلية، فقرة حفظ حقوق مقصودة | طلب كامل يحمي الموقف سواء تمت المصالحة أو أُحيل للمحكمة |
| فحص عرض تسوية مُقترَح | قواعد نصية صريحة، اقتباس حرفي لكل علم خطر | أعلام خطر (إبراء عام، مبلغ/تاريخ غامض) قبل التوقيع |
| قوة الأدلة | تصنيف نوعي لأنواع الأدلة | مؤشر تغطية تنظيمي (ليس تنبؤًا بنتيجة القضية) + قائمة الأدلة الناقصة حسب نوع القضية |
| مسودة لائحة الدعوى | تنسيق نصي من بيانات القضية | مسودة جاهزة للمراجعة قبل التقديم |
| كشف الأثر القانوني | مقارنة ما يُدخل يدويًا بما يُستخرج آليًا من كل مستند مرفوع | معلومات (تواريخ/مبالغ/مواد) موجودة في المستندات وغير مُلتقطة يدويًا بعد |
| تحليل النموذج | اختياري ومقيد بتعليمات grounding | تحليل أعمق مع منع اختلاق مادة أو حكم، ويظل بحاجة لمراجعة |
| معالجة المستندات | PDF/DOCX/TXT/JSON/CSV/صور | نص مستخرج للمراجعة، وليس دليلًا نهائيًا دون مقارنة الأصل |

## المصادر الرسمية الحالية

المصدر الأساسي هو صفحة [نظام العمل في المملكة لدى وزارة الموارد البشرية والتنمية الاجتماعية](https://www.hrsd.gov.sa/knowledge-centre/decisions-and-regulations/regulation-and-procedures/%D9%86%D8%B8%D8%A7%D9%85-%D8%A7%D9%84%D8%B9%D9%85%D9%84)، ومنها نسخة [PDF الرسمية لنظام العمل](https://www.hrsd.gov.sa/sites/default/files/2025-11/labor-law.pdf). توضح صفحة الوزارة تاريخ النظام والتعديلات، ومن بينها التعديل بالمرسوم الملكي م/44 بتاريخ 8/2/1446هـ. يوجد أيضًا رابط [اللائحة التنفيذية لنظام العمل وملحقاتها](https://www.hrsd.gov.sa/knowledge-centre/decisions-and-regulations/regulation-and-procedures/%D8%A7%D9%84%D9%84%D8%A7%D8%A6%D8%AD%D8%A9-%D8%A7%D9%84%D8%AA%D9%86%D9%81%D9%8A%D8%B0%D9%8A%D8%A9-%D9%84%D9%86%D8%B8%D8%A7%D9%85-%D8%A7%D9%84%D8%B9%D9%85%D9%84-%D9%88%D9%85%D9%84%D8%AD%D9%82%D8%A7%D8%AA%D9%87%D8%A7).

كل نتيجة بحث أو مراجعة تحمل بيانات المصدر. تبقى خاصية `verification_required=true` مقصودة؛ التطبيق لا يفترض أن النص المضمن في قاعدة المعرفة يغني عن فتح النسخة الرسمية والتحقق من الإصدار.

```bash

```

عدّل `.env`:


## API القانونية

جميع المسارات التالية، باستثناء `/health` والصفحة الرئيسية، تتطلب الترويسة:

```http
X-App-Token: APP_ACCESS_TOKEN
```

المسارات الأساسية هي `POST /api/legal/review` لحزمة المراجعة (تقبل الآن `claim_amount` اختياريًا لتفعيل فحص التصعيد لمحامٍ)، و`POST /api/legal/obligations` للالتزامات، و`POST /api/legal/risks` للمخاطر، و`POST /api/legal/evidence` للأدلة، و`POST /api/law-search` للبحث الموثق (محرك TF-IDF حقيقي الآن)، و`GET /api/legal/sources` للمصادر الرسمية.

مسارات إضافية من أدوات `legal_tools.py` الموحَّدة: `POST /api/legal/extract-info`، `POST /api/legal/evidence-score`، `GET /api/legal/evidence-gaps/{case_type}`، `POST /api/legal/entitlements/severance`، `POST /api/legal/entitlements/arbitrary-dismissal-floor`، `POST /api/legal/entitlements/wage-delay-rights`، `POST /api/legal/entitlements/overtime`، `POST /api/legal/entitlements/annual-leave`، `POST /api/legal/lawsuit-draft`، `GET /api/legal/litigation-timeline`.

`GET /api/matters/{matter_id}/intelligence` يعيد الآن أيضًا `document_cross_reference` — مقارنة فعلية بين ما أُدخل يدويًا وما استُخرج من نصوص المستندات المرفوعة.

محركات المرحلة 3: `POST /api/legal/deadlines/prescription` و`POST /api/legal/deadlines/all` (تقادم المطالبات، المادة 222)، `POST /api/legal/termination-assessment` (قائمة تحقق مشروعية الإنهاء)، `POST /api/legal/entitlements/full-worksheet` (ورقة الاستحقاقات الشاملة).

المرحلة 4: `POST /api/matters/{matter_id}/correspondence` لاستيعاب نص مراسلات مباشرة (بلا رفع ملف)، و`GET /api/matters/{matter_id}/correspondence-analysis` لتحليلها — مؤشرات لصالح المستخدم وأخرى قد تُستخدم ضده، بقواعد نصية صريحة فقط واقتباس حرفي إلزامي لكل نتيجة.

المرحلة 5: `POST /api/matters/{matter_id}/amicable-settlement/draft` لصياغة طلب تسوية ودية (منصة تراضي) من بيانات قضية حقيقية، و`POST /api/legal/settlement-offer-review` لفحص عرض تسوية مُقترَح قبل التوقيع، و`GET /api/legal/settlement-checklist` لقائمة مرجعية عامة.

## الاختبار

## الخصوصية

التطبيق مخصص لمستخدم واحد، ولا يحتوي على تسجيل مستخدمين أو مشاركة داخلية. لا تضع مفاتيح API أو مستندات حساسة في Git، ولا تسجل النصوص القانونية الخام في سجلات الخادم. استخدم HTTPS أو VPN عند النشر خارج شبكة موثوقة، وحدد سياسة حذف للمستندات المرفوعة.

## طبقات الحماية والتحليل القصوى

أضيفت طبقة استيعاب منظمة تحفظ التواريخ والمبالغ وإشارات الأجر والبريد والهواتف والإشارات النظامية مع النص المستخرج، مع إبقاء كل إشارة بحاجة إلى تحقق بشري. كما يحفظ رفع المستند بصمة SHA-256 للملف الأصلي وحجمه ونوعه ونسخة الأصل الثنائية محليًا، ويولد حدث حيازة ببصمة مستقلة يمكن التحقق منها عبر `GET /api/documents/{document_id}/integrity`.

يقدم `GET /api/matters/{matter_id}/intelligence` تحليلًا مترابطًا للوقائع والمطالبات والمستندات والمواعيد وروابط الأدلة، ويعرض درجة جاهزية ونواقص وتناقضات وآثارًا عمالية وسلامة المستندات، **وكشف أثر قانوني فعلي من نصوص المستندات المرفوعة**. وتوفر `GET /api/procedure/amicable_settlement/requirements` و`GET /api/procedure/lawsuit/requirements` متطلبات إجرائية مرتبطة بمصادر رسمية مع اشتراط فتح المصدر والتحقق من النسخة.

يوفر `GET /api/backup` أرشيفًا خاصًا يضم قاعدة البيانات والأصول الثنائية وبيانًا تعريفيًا. الأرشيف غير مشفر تلقائيًا؛ يجب حفظه داخل حاوية مشفرة وعدم مشاركته أو وضعه في مستودع عام.

## سجل إعادة الهيكلة (المراحل صفر–2)

نُفِّذت إعادة هيكلة جوهرية موثَّقة بالكامل في ثلاثة تقارير منفصلة — **اقرأها قبل أي تعديل إضافي**، فهي تشرح أسباب كل قرار بالدليل الرقمي لا بالوصف فقط:

- `PHASE_0_MIGRATION_NOTES.md` — توحيد `legal_tools_advanced.py` و`litigation_tools.py` و`legal_intelligence.py` في `legal_tools.py` واحد، وإصلاح خطأ حسابي فعلي في تعويض الفصل التعسفي (كانت الصيغة القديمة تُظهر للموظف طويل الخدمة أقل من حقه القانوني الأدنى)، وحذف كل مخرج مالي بلا سند نظامي، وربط `policies.py` فعليًا لأول مرة.
- `PHASE_1_MIGRATION_NOTES.md` — تنظيف `law_text.txt` بتطبيع NFKC حتمي (لا يحتاج ملفات PDF أصلية خلافًا لما افتُرض ابتداءً)، محلل أعداد ترتيبية عربية يفهم ما بعد المائة (كانت مواد كاملة تُفقد بصمت)، ومحرك بحث TF-IDF فعلي يستبدل عدّ الكلمات الحرفي.
- `PHASE_2_MIGRATION_NOTES.md` — محرك ربط فعلي بين المستندات المرفوعة والوقائع/الطلبات المُدخلة يدويًا (`document_cross_reference`)، مبني على اكتشاف أن `extracted_text` كان مخزَّنًا في قاعدة البيانات لكن غير مقروء أبدًا من أي محرك تحليل.
- `PHASE_3_MIGRATION_NOTES.md` — ثلاثة محركات جديدة (مواعيد وتقادم، مشروعية الإنهاء، ورقة عمل شاملة)، وإصلاح تلوّث فهرس البحث (مواد من أنظمة غير عمالية كانت تُصنَّف "عالية الثقة" خطأً).
- `PHASE_4_MIGRATION_NOTES.md` — محرك تحليل المراسلات الإلكترونية: قواعد نصية صريحة فقط (لا AI)، اقتباس حرفي إلزامي، تفسيرات متعددة لا حكم جازم، ربط متقاطع وجدول زمني.
- `PHASE_5_MIGRATION_NOTES.md` — صياغة طلب التسوية الودية عبر منصة تراضي (مؤكَّدة التسمية ببحث مباشر)، بفقرة حفظ حقوق تحمي الموقف سواء تمت المصالحة أو أُحيل الملف للمحكمة، وفحص عروض التسوية قبل التوقيع.

**ملفات مُهمَلة** (موسومة بتعليق إهمال صريح في أعلى كل منها، ولم تعد مستوردة من `server.py`): `legal_tools_advanced.py`، `litigation_tools.py`. يمكن حذفهما بعد التأكد أن لا كود خارجي (واجهة `web/` القديمة مثلًا) يستوردهما مباشرة.

**غير موصول بعد عمدًا** (مبني، لكن يحتاج قرارًا أو بيانات لم تتوفر بعد): `analysis_engine.py` (تحليل 18 محورًا)، `cognitive_core.py`. مرشحان لمرحلة لاحقة بعد ترقية محرك البحث إلى تضمينات حقيقية.

## الحدود التي يجب إعلانها بوضوح

التطبيق لا يدخل تلقائيًا إلى ناجز أو منصة التسوية الودية، ولا يرسل الدعوى أو يرفعها نيابة عن المستخدم. OCR العربي يعتمد على الأدوات المتاحة وقد يحتاج مراجعة الأصل، خصوصًا للصور والخط اليدوي والجداول. النسخ الاحتياطي الحالي ZIP غير مشفر تلقائيًا، ولذلك يجب تشفيره خارجيًا قبل التخزين أو النقل. البصمة وسلسلة الحيازة داخلية تنظيمية وليست شهادة خبرة رقمية أو اعتمادًا قضائيًا مستقلًا. محرك البحث TF-IDF حقيقي لكنه ليس فهمًا دلاليًا كاملًا — لن يربط مرادفًا لا يشارك جذر الكلمة. **48% من مواد قاعدة المعرفة الموسّعة (المستخرجة آليًا من `law_text.txt`) معلَّمة `needs_verification=true`** ويجب مراجعتها مقابل مصدر رسمي قبل الاستشهاد بها في أي مستند فعلي؛ الـ25 مادة المُدخلة يدويًا في `legal_database.py` هي الأعلى ثقة دائمًا.


## طبقة الدمج الموحدة — تحديث 2026-10-13

أصبحت الواجهة الرسمية للتشغيل هي `web/` عبر خادم FastAPI، مع توحيد محركات القضية، الحقوق، الأدلة، الفحص، وسجل Repository داخل مسار API واحد. الأدوار المسموحة هي: **محامي، مستشار قانوني، مستشار عمالي**.

أضيفت المسارات التالية:

- `GET /api/roles`
- `GET /api/matters/{matter_id}/advanced-review`
- `GET /api/matters/{matter_id}/case-theory`
- `POST /api/matters/{matter_id}/rights/analyze`
- `GET /api/matters/{matter_id}/repository-rights`
- `GET /api/matters/{matter_id}/legal-statements`
- `POST /api/matters/{matter_id}/right-review`
- `GET /api/matters/{matter_id}/document-inspections`
- `GET /api/matters/{matter_id}/discovered-rights`

رفع المستند مع `matter_id` يشغل استخراج النص، سجل التغطية، مؤشرات الحقوق غير المذكورة، وحفظ الأصل وبصمته. كما تُنشأ لكل قضية مراحل إجرائية محفوظة وقابلة للتحديث من الاستقبال حتى الإغلاق.

تم حذف `legal_tools_advanced.py` و`litigation_tools.py` بعد نقل الاستيرادات إلى `legal_tools.py`، وأصبح فحص المخاطر يختار قواعد عمالية متخصصة عند اكتشاف سياق نزاع عمالي بدل عرض تصنيفات العقود التجارية العامة.
